# Reflection Report

**Challenges.** The hardest part was making the comparison fair. Each framework flushes the DOM differently, so every app exposes the same four operations and resolves only after its own flush (`flushSync` in React and Svelte, `nextTick` in Vue, `detectChanges` in Angular). Each also needed its own optimisation: React needed `memo` plus stable `useCallback` handlers, otherwise every row re-rendered on any change; Angular needed `trackBy` on `*ngFor`; Vue and Svelte wrap the list in deep reactive proxies, which proved costly for splicing large arrays.

**Effect of each approach.** React's virtual DOM diff, helped by `memo`, rendered 1000 rows fastest (37.6 ms) and retained the least heap (1.7 MB). Angular's dirty-checking was close behind on warm renders but slowest on cold start (152 ms), reflecting its larger runtime. Vue's and Svelte's proxy-based reactivity is excellent for targeted updates but allocates more per item (3.6-3.8 MB). Svelte's compiled output was the smallest bundle (15.6 KB gzip, versus 69 KB for React) yet its first render of 1000 rows was not faster, and deleting from the front of a 1000-item proxied array was the slowest case (4.2 ms).

**Best performer.** React won initial rendering and cold start; Svelte and Vue won on bundle size; updating 50 tasks was effectively a tie (2.2-2.8 ms, inside the noise); React and Angular were quickest at deletion. The differences are a few milliseconds, standard deviations are large, and this was a single headless Chromium run in a sandbox, so I would not generalise: a different implementation (for example, non-keyed rendering) could reorder the results.
